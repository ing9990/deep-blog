비트마스크는 데이터를 CPU의 물리적 단위에 정렬하는 표현 방식입니다. 정수 하나의 각 비트를 플래그로 쓰면, 64 크기의 집합의 합집합, 교집합이 CPU 명령 한 개로 끝납니다. 이 글에서는 그 매핑이 어떻게 자연스럽게 따라오는지, 그리고 어디에 쓰면 빛나고 어디에 쓰면 어긋나는지를 살펴봅니다.

## 비트마스크란

비트마스크는 정수 한 개의 각 비트를 <E>해당 요소가 집합에 속하는지</E> 표시하는 플래그로 사용하는 기법입니다. 32비트 정수 하나로 32개 요소 집합을, 64비트 정수 하나로 64개 요소 집합을 나타낼 수 있습니다.

가령 4명의 친구 `{민수, 영희, 철수, 지수}` 가 있다고 합시다. 각 사람에게 비트 위치를 부여합니다.

| 비트 인덱스 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|
| 이름 | 지수 | 철수 | 영희 | 민수 |

<E>민수와 철수가 모임에 왔다</E>는 상태는 비트 패턴 `0101` 로 표현됩니다.

| 비트 | 0 | 1 | 0 | 1 |
|---|---|---|---|---|
| 이름 | 지수 (X) | 철수 (O) | 영희 (X) | 민수 (O) |

이진수 `0101` 은 십진수로 5 입니다. 즉 정수 5 하나가 `{민수, 철수}` 라는 집합 전체를 표현합니다. 같은 일을 `bool[4]` 배열로도 할 수 있지만, 비트마스크는 메모리를 32~64배 줄이면서 집합 연산을 CPU 1사이클로 처리하는 두 이점을 동시에 가져옵니다.

코드로 보면 이렇게 다룹니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="bitmask-basic.c"
    unsigned int set = 0;             // 빈 집합
    set |= (1U << 0);                 // 민수 추가     → 0001 (= 1)
    set |= (1U << 2);                 // 철수 추가     → 0101 (= 5)
    int has_chulsoo = (set >> 2) & 1; // 철수가 있나?  → 1
    set &= ~(1U << 0);                // 민수 제거     → 0100 (= 4)
    ```
  </Tab>
  <Tab label="Java">
    ```java title="BitmaskBasic.java"
    int set = 0;                      // 빈 집합
    set |= (1 << 0);                  // 민수 추가     → 0001 (= 1)
    set |= (1 << 2);                  // 철수 추가     → 0101 (= 5)
    int hasChulsoo = (set >> 2) & 1;  // 철수가 있나?  → 1
    set &= ~(1 << 0);                 // 민수 제거     → 0100 (= 4)
    ```
  </Tab>
</Tabs>

집합 전체에 대한 연산도 한 줄입니다.

<Tabs group="lang">
  <Tab label="C">

    ```c title="bitmask-set-ops.c"
    unsigned int A = 0b1010;    // {1, 3}
    unsigned int B = 0b1100;    // {2, 3}

    unsigned int I = A & B;     // 교집합 = 0b1000 = {3}
    unsigned int D = A & ~B;    // 차집합 A-B = 0b0010 = {1}
    unsigned int X = A ^ B;     // 대칭차 = 0b0110 = {1, 2}
    ```
  </Tab>
  <Tab label="Java">

핵심 매핑은 <E>비트 1개 = 요소 한 개의 소속 여부</E> 입니다. 이 단순한 매핑에서 모든 연산이 파생됩니다.

## 왜 정수 하나로

비트마스크가 없으면 집합을 두 가지 방법 중 하나로 표현합니다.

첫 번째는 불리언 배열 `bool[N]`. 각 인덱스가 요소 번호, 값이 소속 여부입니다. 읽기·쓰기는 $O(1)$ 로 빠르지만, 두 집합의 합집합·교집합을 구하려면 N개 인덱스를 모두 순회해야 합니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="bool-array-union.c"
    bool A[64], B[64], out[64];
    for (int i = 0; i < 64; i++) {
        out[i] = A[i] || B[i];   // 64번 반복
    }
    ```
  </Tab>
  <Tab label="Java">
    ```java title="BoolArrayUnion.java"
    boolean[] A = new boolean[64];
    boolean[] B = new boolean[64];
    boolean[] out = new boolean[64];
    for (int i = 0; i < 64; i++) {
        out[i] = A[i] || B[i];   // 64번 반복
    }
    ```
  </Tab>
</Tabs>

두 번째는 해시 셋(`HashSet`). 요소가 sparse 하거나 N이 매우 클 때는 좋지만, 각 요소마다 객체 헤더와 해시 버킷, 링크 포인터로 수십 바이트가 듭니다. 4개 요소를 담으려고 200~300 바이트를 쓰는 셈입니다. 합집합도 모든 요소를 순회해 옮겨 담아야 합니다.

이 둘과 비트마스크의 차이는 **CPU가 다루는 단위**에서 옵니다. CPU의 ALU는 32비트 또는 64비트 정수에 대해 AND/OR/XOR을 한 사이클에 실행합니다. 그 한 번의 연산이 32개 또는 64개 비트 모두에 동시에 적용됩니다.

| 작업 | bool[64] 합집합 | 비트마스크 합집합 |
|---|---|---|
| 메모리 | 64 바이트 | 8 바이트 (long long) |
| 연산 횟수 | 64회 OR | 1회 OR |
| 메모리 접근 | 64회 (loop) | 1회 (register) |

같은 결과를 얻지만 위는 64번 메모리 접근과 64번 OR 연산이고, 아래는 레지스터에서 OR 한 번입니다. <E>N번 루프 → 1사이클</E> 로 바뀌는 이유는 비트들이 한 정수 안에 packed 되어 있어서 CPU가 64개를 한꺼번에 처리하기 때문입니다. 이게 비트마스크의 본질입니다.

이 글을 다 읽으면 다음 다섯 가지를 이해하게 됩니다.

- 비트마스크가 왜 메모리와 속도를 동시에 줄이는가 (CPU의 word 단위 연산)
- AND/OR/XOR/NOT/Shift 가 집합의 어떤 연산에 대응하는가
- 부분집합 순회를 `for (s = mask; s; s = (s-1) & mask)` 한 줄로 쓰는 이유
- 비트 DP에서 상태 압축이 왜 가능한가
- 언제 비트마스크가 부적합한가 (N이 64를 크게 넘거나 집합이 sparse 할 때)

## 동작 원리

<Callout type="warning" title="이 구조를 이해하는 핵심">
  비트마스크의 모든 사용 패턴은 다섯 가지 기본 연산자(`&`, `|`, `^`, `~`, `<<`/`>>`)의 조합입니다. 각 연산자가 집합 연산의 어디에 대응하는지를 한 번 익히면, popcount나 부분집합 순회 같은 응용은 그 위에서 자연스럽게 따라옵니다.
</Callout>

### 단일 비트 조작

요소 `k` (0-indexed) 를 다루는 네 가지 연산입니다.

| 연산 | 의미 | C 표현 |
|---|---|---|
| Add | k 번째 요소를 집합에 추가 | `set \|= (1U << k)` |
| Remove | k 번째 요소를 제거 | `set &= ~(1U << k)` |
| Check | k 번째 요소가 있는가 | `(set >> k) & 1` |
| Toggle | k 번째 요소를 뒤집기 | `set ^= (1U << k)` |

각 표현이 왜 그 모양인지 살펴봅니다.

`1U << k` 는 k 번째 비트만 1이고 나머지는 0인 마스크를 만듭니다. `k = 2` 라면 `0000...0100`. 이걸 OR 하면 해당 비트만 1로 켜지고 나머지는 그대로 (OR의 항등원이 0이라). 이것이 Add 입니다.

Remove 는 반대로 k 번째 비트만 0이고 나머지는 1인 마스크가 필요합니다. 이게 `~(1U << k)`. 그것과 AND 하면 해당 비트만 0으로, 나머지는 그대로 (AND의 항등원이 1이라). OR 로 안 되는 이유는 OR 은 비트를 1로만 만들 수 있고 0으로 되돌릴 수 없기 때문입니다.

Toggle 은 XOR 입니다. XOR 의 정의가 <E>두 비트가 다르면 1, 같으면 0</E> 이라 마스크의 1 자리에서는 비트가 뒤집히고 마스크의 0 자리는 그대로 보존됩니다. 비트를 뒤집고 싶으면 XOR 이라는 직관이 여기서 나옵니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="single-bit-ops.c"
    unsigned int set = 0b1010;     // {1, 3}

    set |= (1U << 0);              // Add 0    → 0b1011 = {0, 1, 3}
    set &= ~(1U << 1);             // Remove 1 → 0b1001 = {0, 3}
    int has2 = (set >> 2) & 1;     // Check 2  → 0
    set ^= (1U << 3);              // Toggle 3 → 0b0001 = {0}
    ```
  </Tab>
  <Tab label="Java">
    ```java title="SingleBitOps.java"
    int set = 0b1010;              // {1, 3}

    set |=  (1 << 0);              // Add 0    → 0b1011 = {0, 1, 3}
    set &= ~(1 << 1);              // Remove 1 → 0b1001 = {0, 3}
    int has2 = (set >> 2) & 1;     // Check 2  → 0
    set ^=  (1 << 3);              // Toggle 3 → 0b0001 = {0}
    ```
  </Tab>
</Tabs>

`1U` 와 `1` 의 차이를 짚어둘 필요가 있습니다. C에서 `1` 은 `int` (signed)라 `1 << 31` 은 처리 환경에 따라 정의되지 않을 수 있습니다. 31비트 이상을 다룰 때는 `1U` (unsigned) 를, 64비트면 `1ULL` 을 씁니다. Java에서는 `int` 가 항상 부호 있는 32비트지만 시프트 결과가 정의돼 있어 `1 << 31` 이 `Integer.MIN_VALUE` 가 됩니다. 64비트 마스크면 `1L << k` 로 `long` 을 명시합니다.

### 집합 연산 매핑

집합 단위 연산은 비트 단위 연산과 일대일 대응합니다.

| 집합 연산 | 비트 연산 | 직관 |
|---|---|---|
| 합집합 (∪) | `A \| B` | 어느 한쪽이라도 1이면 1 |
| 교집합 (∩) | `A & B` | 양쪽 다 1일 때만 1 |
| 차집합 (A − B) | `A & ~B` | A에서 B의 비트를 꺼버림 |
| 대칭차 (A △ B) | `A ^ B` | 한쪽에만 있는 것 |

이 매핑이 자연스러운 이유는, 각 비트 위치를 보면 결국 두 불리언 값의 논리 연산 그대로이기 때문입니다. <E>요소 k가 합집합에 있는가</E> 는 <E>A에 있거나 B에 있다</E> 와 같고, 이건 `A_k OR B_k` 입니다. 비트 단위로 OR을 64번 하는 대신 정수 단위로 OR을 1번 하면, 64개 위치가 동시에 계산됩니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="set-algebra.c"
    unsigned int A = 0b1010;       // {1, 3}
    unsigned int B = 0b1100;       // {2, 3}

    unsigned int U = A | B;        // 0b1110 = {1, 2, 3}
    unsigned int I = A & B;        // 0b1000 = {3}
    unsigned int D = A & ~B;       // 0b0010 = {1}      // A 에서 B 빼기
    unsigned int X = A ^ B;        // 0b0110 = {1, 2}
    ```
  </Tab>
  <Tab label="Java">
    ```java title="SetAlgebra.java"
    int A = 0b1010;                // {1, 3}
    int B = 0b1100;                // {2, 3}

    int U = A | B;                 // 0b1110 = {1, 2, 3}
    int I = A & B;                 // 0b1000 = {3}
    int D = A & ~B;                // 0b0010 = {1}      // A 에서 B 빼기
    int X = A ^ B;                 // 0b0110 = {1, 2}
    ```
  </Tab>
</Tabs>

### popcount

집합의 요소 개수, 즉 켜진 비트 수를 세는 연산을 popcount 라고 부릅니다. 가장 단순한 방법은 비트를 하나씩 보는 것이지만, 더 영리한 방법인 **Brian Kernighan 의 알고리즘**이 자주 쓰입니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="popcount-kernighan.c"
    int popcount(unsigned int x) {
        int count = 0;
        while (x) {
            x &= (x - 1);   // 켜진 비트 중 가장 낮은 것을 끔
            count++;
        }
        return count;
    }
    ```
  </Tab>
  <Tab label="Java">
    ```java title="PopcountKernighan.java"
    static int popcount(int x) {
        int count = 0;
        while (x != 0) {
            x &= (x - 1);   // 켜진 비트 중 가장 낮은 것을 끔
            count++;
        }
        return count;
    }
    ```
  </Tab>
</Tabs>

핵심은 `x & (x-1)` 이 가장 낮은 켜진 비트를 끈다는 사실입니다. 8비트 예제로 단계별 변화를 봅니다.

| 단계 | x (이진) | x - 1 (이진) | x & (x-1) |
|---|---|---|---|
| 시작 | `1011 0100` | `1011 0011` | `1011 0000` (위치 2 사라짐) |
| 1회 후 | `1011 0000` | `1010 1111` | `1010 0000` (위치 4 사라짐) |
| 2회 후 | `1010 0000` | `1001 1111` | `1000 0000` (위치 5 사라짐) |
| 3회 후 | `1000 0000` | `0111 1111` | `0000 0000` (위치 7 사라짐) |

`x - 1` 은 가장 낮은 켜진 비트와 그 아래 비트들을 모두 뒤집습니다. AND 하면 그 비트와 아래 비트들이 모두 0이 됩니다. 결과적으로 가장 낮은 켜진 비트만 사라진 모양입니다. 이 알고리즘은 켜진 비트 수만큼만 반복하므로, 비트가 sparse 한 마스크에서 32회 모두 도는 단순 루프보다 빠릅니다.

실무에서는 직접 구현할 일이 거의 없습니다. 현대 CPU는 popcount 를 하드웨어 명령어 `POPCNT` 로 지원하며, GCC/Clang 의 `__builtin_popcount(x)`, Java 의 `Integer.bitCount(x)` 가 이를 사용합니다. Kernighan 알고리즘은 <E>왜 빠른가</E> 의 직관용입니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="popcount-builtin.c"
    int n = __builtin_popcount(set);          // unsigned int
    int m = __builtin_popcountll(big_set);    // unsigned long long
    ```
  </Tab>
  <Tab label="Java">
    ```java title="PopCount.java"
    int n = Integer.bitCount(set);
    int m = Long.bitCount(bigSet);
    ```
  </Tab>
</Tabs>

### 가장 낮은 비트

집합에서 <E>가장 작은 요소 하나</E> 를 뽑고 싶을 때 쓰는 관용구가 `x & -x` 입니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="lowest-bit.c"
    unsigned int lowest = x & (-x);   // 가장 낮은 켜진 비트만 남는다
    int index = __builtin_ctz(x);     // 그 비트의 인덱스 (count trailing zeros)
    ```
  </Tab>
  <Tab label="Java">
    ```java title="LowestBit.java"
    int lowest = x & (-x);                       // 가장 낮은 켜진 비트만 남는다
    int index = Integer.numberOfTrailingZeros(x);// 그 비트의 인덱스
    ```
  </Tab>
</Tabs>

`-x` 는 2의 보수 표현에서 x 의 모든 비트를 뒤집고 1을 더한 값입니다. `x = 0b10110100` 이면 `-x = 0b01001100`. AND 하면 가장 낮은 켜진 비트 `0b00000100` 만 남습니다. Fenwick Tree (Binary Indexed Tree) 가 이 트릭을 핵심 인덱싱에 사용합니다.

### 부분집합 순회

비트마스크의 가장 강력한 패턴 중 하나가 어떤 집합 `mask` 의 모든 부분집합을 한 번씩 순회하는 것입니다. 비트 DP에서 자주 등장합니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="subset-enumeration.c"
    unsigned int mask = 0b1011;    // 부분집합을 돌고 싶은 집합 {0, 1, 3}

    for (unsigned int s = mask; s > 0; s = (s - 1) & mask) {
        // s 는 mask 의 부분집합 중 하나 (공집합 제외)
        print_set(s);
    }
    // 공집합도 처리하려면 루프 뒤에 s = 0 한 번 더
    ```
  </Tab>
  <Tab label="Java">
    ```java title="SubsetEnumeration.java"
    int mask = 0b1011;             // 부분집합을 돌고 싶은 집합 {0, 1, 3}

    for (int s = mask; s > 0; s = (s - 1) & mask) {
        // s 는 mask 의 부분집합 중 하나 (공집합 제외)
        printSet(s);
    }
    // 공집합도 처리하려면 루프 뒤에 s = 0 한 번 더
    ```
  </Tab>
</Tabs>

이 루프는 mask 의 부분집합을 정확히 한 번씩, 큰 것부터 작은 것 순으로 순회합니다. mask = `0b1011` 일 때 실제로 어떤 값을 거치는지 보면 패턴이 명확합니다.

| 단계 | s (이진) | s - 1 | (s - 1) & mask | 의미 |
|---|---|---|---|---|
| 0 | `1011` | (시작) | (시작) | mask 자체 = {0, 1, 3} |
| 1 | `1010` | `1001` | `1001` | {1, 3} |
| 2 | `1001` | `1000` | `1000` | {3} |
| 3 | `1000` | `0111` | `0011` | {0, 1} |
| 4 | `0011` | `0010` | `0010` | {1} |
| 5 | `0010` | `0001` | `0001` | {0} |
| 6 | `0001` | `0000` | `0000` | 공집합 → 종료 |

`s - 1` 은 s 의 가장 낮은 켜진 비트를 끄고 그 아래 비트를 모두 켭니다 (popcount에서 본 부산물). 그러면 mask 의 비트가 아닌 위치도 켜질 수 있는데, `& mask` 로 다시 mask 의 비트만 남깁니다. 결과적으로 <E>이전 부분집합보다 한 단계 작은 mask 의 부분집합</E> 으로 정확히 떨어집니다.

요소 수가 `n` 이면 부분집합 개수가 $2^n$ 이라 이 루프는 $O(2^n)$ 입니다. mask 자체가 모든 비트인 `(1 << n) - 1` 이 아니라 일부만 켜져 있으면, 그 일부의 부분집합만 순회하므로 비트 DP의 전이에 정확히 맞습니다.

### 비트 DP

지금까지의 모든 도구가 모이는 응용이 비트 DP (상태 압축 DP) 입니다. <E>방문한 도시 집합</E> 처럼 부분집합이 상태인 문제에서, 그 집합을 정수로 압축해 DP 테이블의 인덱스로 씁니다.

<Callout type="error" title="핵심 통찰: 비트마스크는 트릭이 아니라 표현 방식이다">
  64비트 정수는 어차피 CPU가 한 사이클에 다루는 단위입니다. 그걸 그대로 64요소 집합으로 쓰면 하드웨어가 알아서 모든 비트를 동시에 처리해 줍니다. 비트마스크가 트릭처럼 보이는 이유는 우리가 평소에 데이터를 추상화로 다루기 때문이지, CPU 입장에서는 가장 자연스러운 형태입니다.
</Callout>

대표 예시는 **외판원 문제(TSP) 의 Held-Karp 알고리즘** 입니다. N개 도시를 모두 한 번씩 방문하는 최소 비용 경로를 찾는 문제로, 단순 순열 탐색은 $O(N!)$ 이지만 비트 DP로 $O(2^N \cdot N^2)$ 까지 줄일 수 있습니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="tsp-bitmask-dp.c"
    // dp[mask][i] = mask 에 포함된 도시들을 모두 방문했고 현재 i 에 있을 때 최소 비용
    int dp[1 << N][N];

    // 초기 상태: 0번 도시에서 시작
    dp[1][0] = 0;

    for (int mask = 1; mask < (1 << N); mask++) {
        for (int i = 0; i < N; i++) {
            if (!((mask >> i) & 1)) continue;       // i 가 mask 에 없으면 skip

            for (int j = 0; j < N; j++) {
                if ((mask >> j) & 1) continue;       // 이미 방문한 도시는 skip
                int next_mask = mask | (1 << j);     // j 를 추가
                dp[next_mask][j] = min(
                    dp[next_mask][j],
                    dp[mask][i] + dist[i][j]
                );
            }
        }
    }
    ```
  </Tab>
  <Tab label="Java">
    ```java title="TspBitmaskDp.java"
    // dp[mask][i] = mask 의 도시들을 방문했고 현재 i 에 있을 때 최소 비용
    int[][] dp = new int[1 << N][N];

    // 초기 상태: 0번 도시에서 시작
    dp[1][0] = 0;

    for (int mask = 1; mask < (1 << N); mask++) {
        for (int i = 0; i < N; i++) {
            if (((mask >> i) & 1) == 0) continue;    // i 가 mask 에 없으면 skip

            for (int j = 0; j < N; j++) {
                if (((mask >> j) & 1) != 0) continue;// 이미 방문한 도시는 skip
                int nextMask = mask | (1 << j);      // j 를 추가
                dp[nextMask][j] = Math.min(
                    dp[nextMask][j],
                    dp[mask][i] + dist[i][j]
                );
            }
        }
    }
    ```
  </Tab>
</Tabs>

상태가 `(방문 집합, 현재 위치)` 두 차원이라 시간 복잡도가 $O(2^N \cdot N^2)$ 입니다. $N = 20$ 정도까지는 충분히 풉니다 ($2^{20} \approx 10^6$). N 개 도시 집합을 정수 N 비트로 표현 가능한 게 비트마스크의 결정적 기여입니다. `bool[N]` 으로 같은 일을 하면 DP 테이블의 키가 배열이 되어 버려 인덱싱이 바로 안 됩니다.

## 적합한 상황

비트마스크는 만능이 아닙니다. 데이터의 형태와 연산의 종류가 맞아야 효과가 납니다.

### 적합한 경우

요소 수 N이 작고 미리 알려져 있는 경우 (N ≤ 64) 가 첫 번째입니다. 64비트 정수 하나에 표현 가능한 것이 가장 깔끔합니다. N이 32 이하면 `unsigned int`, 64 이하면 `unsigned long long` (C) 또는 `long` (Java). N이 64를 넘어가도 비트마스크 기법 자체는 가능하지만, 정수 한 개로는 안 되고 비트 배열(bitset) 로 확장해야 해 코드의 단순함이 사라집니다.

집합 전체를 자주 비교·합치고 싶을 때도 적합합니다. 합집합·교집합·차집합·대칭차를 매 단계 계산해야 하는 알고리즘에서 비트마스크는 압도적입니다. `bool[N]` 으로 같은 작업을 하면 N번 루프, 비트마스크는 1사이클입니다. N = 64 이면 64배 차이, 캐시 적중률까지 고려하면 그 이상.

부분집합 자체가 상태인 비트 DP 도 비트마스크의 본진입니다. TSP, 외판원, 부분집합 합 문제, 그래프의 도미네이팅 셋, 직사각형 타일링(broken profile DP) 등에서 방문 집합이나 선택된 집합이 DP 의 키로 쓰입니다. 정수 한 개를 인덱스로 쓰면 `dp[1 << N]` 이라는 단순한 배열 하나로 끝납니다.

상수 시간 멤버십 검사가 필요한 작은 lookup table 도 좋은 응용입니다. 예를 들어 ASCII 문자 256개 중 <E>특정 부호 문자인지</E> 판정하는 경우, 256비트 비트맵을 미리 만들어두면 다음 한 줄로 끝납니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="ascii-bitmap.c"
    static unsigned long long bitmap[4];   // 256 비트

    int is_special(unsigned char c) {
        return (bitmap[c >> 6] >> (c & 63)) & 1ULL;
    }
    ```
  </Tab>
  <Tab label="Java">
    ```java title="AsciiBitmap.java"
    static long[] bitmap = new long[4];    // 256 비트

    static boolean isSpecial(byte c) {
        int idx = c & 0xFF;
        return ((bitmap[idx >> 6] >> (idx & 63)) & 1L) != 0;
    }
    ```
  </Tab>
</Tabs>

`switch-case` 보다 빠르고 분기 예측에도 친숙합니다.

### 부적합한 경우

요소 수가 매우 크거나 unbounded 일 때는 비트마스크가 맞지 않습니다. 요소가 수만~수백만이면 정수 하나로 표현 못 합니다. 비트 배열(`std::bitset`, `BitSet`)로 확장하면 가능하지만, 그 시점부터는 랜덤 접근과 동적 크기가 필요한지 따져 `HashSet` 이 더 나을 수 있습니다.

집합이 sparse 한 경우에도 부적합합니다. N = 10000 이고 평균 요소 수가 5개라면, 10000비트 = 1250바이트를 매 집합마다 들고 다니는 셈입니다. 이때는 `HashSet<Integer>` 또는 정렬된 배열이 메모리·이터레이션 모두 유리합니다. 밀도(요소 수 / N) 가 50% 이상이 비트마스크의 손익분기점이라는 경험칙이 있습니다.

요소가 정수 인덱스가 아니면 매핑 변환 단계가 필요합니다. 요소가 문자열·객체·튜플이라면 비트 위치에 매핑하는 변환을 별도 해시맵으로 유지해야 하고, 그러면 비트마스크의 단순함이 사라집니다. 그냥 `HashSet<T>` 가 더 직관적입니다.

비트 위치의 의미가 자주 바뀌거나 늘어나는 경우도 부적합합니다. <E>3번 비트는 결제 완료, 4번 비트는 배송 시작</E> 같은 상태 플래그 모음을 비트마스크로 만들었다가 도메인 상태가 늘어나면, 비트 위치 의미가 코드 곳곳에 흩어져 디버깅이 매우 어려워집니다. 이런 경우는 `enum` + `Set<Status>` 가 더 적합합니다. **알고리즘 영역에서는 비트마스크가 강하지만 도메인 모델링에서는 약합니다.**

### 손익분기 정리

| 상황 | 추천 자료구조 |
|---|---|
| N ≤ 64, 집합 연산 잦음, 정수 인덱스 | 비트마스크 |
| N > 64, 밀도 ≥ 50% | bitset (`std::bitset` / `java.util.BitSet`) |
| N 큼 + sparse | HashSet |
| 도메인 상태 플래그 (의미 변경 잦음) | enum + Set |

비트마스크는 알고리즘 문제 풀이와 시스템 저수준 코드(커널, 컴파일러, 데이터베이스 비트맵 인덱스) 에서 빛납니다. 비즈니스 로직에서는 가독성을 더 중시하는 게 보통입니다.

## 트레이드오프

비트마스크가 빠르고 메모리 효율적인 대신 치르는 대가가 셋 있습니다.

### 가독성 비용

`(set >> k) & 1` 이 <E>k 번째 요소가 있는가</E> 인지 코드만 보고 즉시 이해하지 못하는 사람이 많습니다. `set.contains(k)` 쪽이 의도를 직접 드러냅니다. 이 비용은 팀의 기술 수준과 그 코드가 알고리즘 영역인지 도메인 영역인지에 따라 평가가 갈립니다. 알고리즘 코드에서는 관용구로 받아들여지지만, 결제 도메인 코드에서 비트마스크를 쓰면 코드 리뷰에서 막힙니다.

완화 방법은 매크로(C)나 정적 헬퍼 메서드(Java) 추출입니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="readable-bitmask.c"
    #define HAS(set, k)    (((set) >> (k)) & 1U)
    #define ADD(set, k)    ((set) |= (1U << (k)))
    #define REMOVE(set, k) ((set) &= ~(1U << (k)))

    if (HAS(visited, city)) { ... }
    ```
  </Tab>
  <Tab label="Java">
    ```java title="ReadableBitmask.java"
    static boolean has(int set, int k)    { return ((set >> k) & 1) != 0; }
    static int     add(int set, int k)    { return set |  (1 << k); }
    static int     remove(int set, int k) { return set & ~(1 << k); }

    if (has(visited, city)) { ... }
    ```
  </Tab>
</Tabs>

이름을 부여하면 의도가 드러나지만, 매크로나 헬퍼 자체가 또 다른 학습 비용을 만듭니다. 트레이드오프입니다.

### 확장성 비용

요소 수가 미리 알려져 있어야 합니다. 처음엔 32개로 충분했는데 나중에 50개가 됐다고 가령 합시다. 마스크 타입을 `unsigned int → unsigned long long` (C) 또는 `int → long` (Java) 으로 바꿔야 하고, 코드 곳곳의 `(1U << k)` 도 `(1ULL << k)` 로, Java 라면 `(1L << k)` 로 일괄 수정해야 합니다. 64를 넘어가면 비트 배열로 자료구조를 통째로 갈아야 합니다. 이 비용 때문에 비즈니스 도메인 객체 상태를 비트마스크로 표현하는 건 위험합니다. 도메인은 시간이 지나면 거의 항상 늘어나기 때문입니다.

### 디버깅 비용

`set = 1234567` 을 보고 어떤 요소들이 켜져 있는지 즉시 읽을 수 없습니다. 디버거에서 이진수로 보거나 popcount + 비트 인덱스를 손으로 풀어야 합니다. 알고리즘 문제 풀이에서 작은 N (≤ 20) 까지는 견딜 만하지만, 32~64비트로 가면 디버깅 출력에 helper 함수가 필요해집니다.

<Tabs group="lang">
  <Tab label="C">
    ```c title="bitmask-debug-print.c"
    void print_set(unsigned int set, int n) {
        printf("{");
        for (int i = 0; i < n; i++) {
            if ((set >> i) & 1) printf("%d ", i);
        }
        printf("}\n");
    }
    ```
  </Tab>
  <Tab label="Java">
    ```java title="BitmaskDebugPrint.java"
    static void printSet(int set, int n) {
        StringBuilder sb = new StringBuilder("{");
        for (int i = 0; i < n; i++) {
            if (((set >> i) & 1) != 0) sb.append(i).append(' ');
        }
        sb.append('}');
        System.out.println(sb);
    }
    ```
  </Tab>
</Tabs>

## 마무리

비트마스크의 가치는 데이터 구조를 CPU 와 메모리의 물리적 단위에 정렬한 데서 옵니다. 64비트 정수는 어차피 한 사이클에 다뤄지는 단위이고, 그걸 그대로 64요소 집합으로 쓰면 하드웨어가 알아서 모든 비트를 동시에 처리해 줍니다. 비트마스크가 트릭처럼 보이는 이유는 우리가 평소 데이터를 `Set<Integer>` 같은 추상화로 다루기 때문이지, CPU 입장에서는 가장 자연스러운 형태입니다.

이 관점이 정착되면 Fenwick Tree 의 `i & -i`, 외판원 DP 의 부분집합 인덱스, 데이터베이스의 비트맵 인덱스(InnoDB 페이지 비트맵, PostgreSQL BRIN 등) 가 같은 아이디어의 다른 응용으로 보입니다. 비트마스크는 N ≤ 64 이고 집합 연산이 잦으며 요소가 정수 인덱스인 영역에서 빛나고, 도메인 모델링이나 sparse 한 큰 집합에서는 다른 자료구조가 맞습니다. 이 손익분기를 명확히 알고 쓰는 것이 비트마스크를 잘 다루는 길입니다.
