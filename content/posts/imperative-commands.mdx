## Certification Tip: Imperative Commands

평소에는 대부분 정의 파일(definition files)을 사용하는 선언적 방식으로 작업하게 됩니다. 그렇지만 명령형(imperative) 명령은 일회성 작업을 빠르게 끝내거나 정의 템플릿을 손쉽게 생성하는 데에 도움이 됩니다. 시험 중에 상당한 시간을 아끼는 데에 큰 도움이 됩니다.

시작하기 전에, 아래 명령들과 함께 쓰면 유용한 두 가지 옵션을 익혀 둡시다.

`--dry-run`: 기본적으로 명령을 실행하면 곧바로 리소스가 생성됩니다. 단순히 명령을 시험해 보고 싶다면 `--dry-run=client` 옵션을 사용합니다. 이 옵션은 리소스를 생성하지 않습니다. 대신 리소스가 생성될 수 있는지, 그리고 명령이 올바른지 알려 줍니다.

`-o yaml`: 리소스 정의를 YAML 형식으로 화면에 출력합니다.

위 두 옵션을 리눅스 출력 리다이렉션과 함께 사용하면 리소스 정의 파일을 빠르게 생성할 수 있습니다. 그렇게 받은 파일을 필요에 맞게 수정해 리소스를 만들면, 파일을 처음부터 작성하는 것보다 효율적입니다.

```bash
kubectl run nginx --image=nginx --dry-run=client -o yaml > nginx-pod.yaml
```

## POD

NGINX Pod 만들기

```bash
kubectl run nginx --image=nginx
```

Pod 매니페스트 YAML 파일을 생성합니다(`-o yaml`). 생성은 하지 않습니다(`--dry-run`).

```bash
kubectl run nginx --image=nginx --dry-run=client -o yaml
```

## Deployment

Deployment 만들기

```bash
kubectl create deployment --image=nginx nginx
```

Deployment YAML 파일을 생성합니다(`-o yaml`). 생성은 하지 않습니다(`--dry-run`).

```bash
kubectl create deployment --image=nginx nginx --dry-run=client -o yaml
```

`replicas`가 4인 Deployment 생성하기

```bash
kubectl create deployment nginx --image=nginx --replicas=4
```

`kubectl scale` 명령으로 Deployment의 replicas를 조정할 수도 있습니다.

```bash
kubectl scale deployment nginx --replicas=4
```

또 다른 방법은 YAML 정의를 파일로 저장한 뒤 수정하는 것입니다.

```bash
kubectl create deployment nginx --image=nginx --dry-run=client -o yaml > nginx-deployment.yaml
```

이 YAML 파일에서 `replicas`나 다른 필드를 갱신한 뒤 Deployment를 생성하면 됩니다.

## Service

Pod `redis`의 `6379` 포트를 노출하는 ClusterIP 타입의 Service `redis-service` 만들기

```bash
kubectl expose pod redis --port=6379 --name=redis-service --dry-run=client -o yaml
```

(이 명령은 Pod의 라벨을 자동으로 셀렉터로 사용합니다.)

또는

```bash
kubectl create service clusterip redis --tcp=6379:6379 --dry-run=client -o yaml
```

(이 명령은 Pod의 라벨을 셀렉터로 사용하지 않습니다. 대신 셀렉터를 `app=redis`로 가정합니다. 셀렉터를 옵션으로 전달할 수 없습니다. 그래서 Pod의 라벨 집합이 다르면 잘 동작하지 않습니다. 따라서 파일을 생성한 뒤 셀렉터를 수정하고 Service를 만드는 편이 좋습니다.)

노드의 `30080` 포트로 Pod `nginx`의 `80` 포트를 노출하는 NodePort 타입의 Service `nginx` 만들기

```bash
kubectl expose pod nginx --port=80 --name=nginx-service --type=NodePort --dry-run=client -o yaml
```

(이 명령은 Pod의 라벨을 자동으로 셀렉터로 사용하지만, node port 번호는 지정할 수 없습니다. 정의 파일을 생성한 뒤 node port 값을 직접 추가해야 Pod에 연결되는 Service를 만들 수 있습니다.)

또는

```bash
kubectl create service nodeport nginx --tcp=80:80 --node-port=30080 --dry-run=client -o yaml
```

(이 명령은 Pod의 라벨을 셀렉터로 사용하지 않습니다.)

위의 두 명령 모두 각자 약점이 있습니다. 한쪽은 셀렉터를 받지 못하고, 다른 한쪽은 node port를 받지 못합니다. `kubectl expose` 명령을 사용하는 편을 권장합니다. node port를 지정해야 한다면, 같은 명령으로 정의 파일을 생성한 뒤 nodeport 값을 직접 입력하고 나서 Service를 만들면 됩니다.
