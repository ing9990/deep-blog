Quick Sort는 분할 정복(divide and conquer) 전략으로 동작하는 비교 정렬 알고리즘입니다. 평균 시간 복잡도 $O(n \log n)$로 실무에서 가장 널리 쓰이는 정렬 알고리즘 중 하나이며, 많은 표준 라이브러리가 Quick Sort 또는 그 변형(Introsort, Timsort)을 기본 구현으로 채택합니다.

이 글에서는 Quick Sort의 동작 원리를 단계별로 살펴보고, 직접 인터랙션 가능한 시각화로 확인하며, 주의해야 할 케이스를 짚어봅니다. 동시에 이 페이지는 **Backend Notes 블로그의 모든 MDX 문법을 한눈에 볼 수 있는 스타일 가이드**이기도 합니다.

  이 글의 모든 코드 예제는 동일한 입력 배열 `[38, 27, 43, 3, 9, 82, 10]`을 사용합니다. 각 언어별 구현이 어떻게 다른지 직접 비교해보세요.

## 개요

Quick Sort의 핵심 아이디어는 간단합니다:

1. 배열에서 **피벗**(pivot) 하나를 고릅니다
2. 피벗보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 분할합니다
3. 좌우 각각에 대해 재귀적으로 같은 과정을 반복합니다

데이터베이스 인덱스도 유사한 분할 정복 사고방식을 활용합니다. 인덱스 탐색은 B-Tree를 통해 매 단계 탐색 범위를 절반 가까이로 줄이는 방식인데, Quick Sort의 "피벗으로 분할" 아이디어와 직관적으로 닮아있습니다.

## 알고리즘 단계

Lomuto 파티션 방식을 기준으로 동작을 정리하면:

1. 배열의 마지막 원소를 피벗으로 선택
2. `i = lo - 1` 로 파티션 경계 초기화
3. `j` 를 `lo` 부터 `hi - 1` 까지 순회하며:
   - `arr[j] <= pivot` 이면 `i` 를 1 증가시키고 `arr[i]` 와 `arr[j]` 교환
4. 마지막으로 `arr[i+1]` 와 `arr[hi]`(피벗) 교환
5. 피벗의 최종 위치 `i+1` 을 기준으로 좌우 서브 배열에 재귀 호출

### 의사 코드

```py title="quicksort.py"
def quick_sort(arr, lo, hi):
    if lo < hi:
        pivot_index = partition(arr, lo, hi)
        quick_sort(arr, lo, pivot_index - 1)
        quick_sort(arr, pivot_index + 1, hi)

def partition(arr, lo, hi):
    pivot = arr[hi]
    i = lo - 1
    for j in range(lo, hi):
        if arr[j] <= pivot:  # [!code highlight]
            i += 1
            arr[i], arr[j] = arr[j], arr[i]
    arr[i + 1], arr[hi] = arr[hi], arr[i + 1]
    return i + 1
```

### 언어별 구현

동일한 Lomuto 파티션을 Kotlin과 TypeScript로 옮긴 예입니다. 언어 탭을 전환해 문법 차이를 비교하세요.

<Tabs group="lang">
  <Tab label="Kotlin">
    ```kotlin title="QuickSort.kt"
    fun <T : Comparable<T>> quickSort(arr: MutableList<T>, lo: Int = 0, hi: Int = arr.lastIndex) {
        if (lo >= hi) return
        val pivotIndex = partition(arr, lo, hi)  // [!code highlight]
        quickSort(arr, lo, pivotIndex - 1)
        quickSort(arr, pivotIndex + 1, hi)
    }

    private fun <T : Comparable<T>> partition(arr: MutableList<T>, lo: Int, hi: Int): Int {
        val pivot = arr[hi]
        var i = lo - 1
        for (j in lo until hi) {
            if (arr[j] <= pivot) {
                i++
                val tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp
            }
        }
        val tmp = arr[i + 1]; arr[i + 1] = arr[hi]; arr[hi] = tmp
        return i + 1
    }

    fun main() {
        val nums = mutableListOf(38, 27, 43, 3, 9, 82, 10)
        quickSort(nums)
        println(nums) // [3, 9, 10, 27, 38, 43, 82]
    }
    ```

    Kotlin의 `<T : Comparable<T>>` 제약은 Java의 `<T extends Comparable<T>>` 와 동일합니다. 타입 파라미터를 통해 모든 비교 가능한 타입에 대해 재사용할 수 있습니다.
  </Tab>
  <Tab label="TypeScript">
    ```typescript title="quicksort.ts"
    export function quickSort<T>(arr: T[], compare: (a: T, b: T) => number = defaultCompare): T[] {
      const out = arr.slice()
      sort(out, 0, out.length - 1, compare)
      return out
    }

    function sort<T>(arr: T[], lo: number, hi: number, compare: (a: T, b: T) => number): void {
      if (lo >= hi) return
      const p = partition(arr, lo, hi, compare)
      sort(arr, lo, p - 1, compare)
      sort(arr, p + 1, hi, compare)
    }

    function partition<T>(arr: T[], lo: number, hi: number, compare: (a: T, b: T) => number): number {
      const pivot = arr[hi]
      let i = lo - 1
      for (let j = lo; j < hi; j++) {
        if (compare(arr[j], pivot) <= 0) {
          i++
          ;[arr[i], arr[j]] = [arr[j], arr[i]]
        }
      }
      ;[arr[i + 1], arr[hi]] = [arr[hi], arr[i + 1]]
      return i + 1
    }

    function defaultCompare<T>(a: T, b: T): number {
      return a < b ? -1 : a > b ? 1 : 0
    }
    ```

    TypeScript는 비교 함수를 파라미터로 받아 사용자 정의 정렬 기준을 지원합니다. 기본값 `defaultCompare`로 `<`·`>` 비교를 하며, 필요 시 주입해 숫자 정렬(`(a,b) => a - b`)이나 키 기반 정렬로 확장할 수 있습니다.
  </Tab>
</Tabs>

## 시간 복잡도

| 케이스 | 시간 복잡도 | 설명 |
|---|---|---|
| 최선 | $O(n \log n)$ | 피벗이 항상 배열을 균등하게 분할 |
| 평균 | $O(n \log n)$ | 랜덤 피벗 선택 시의 기대값 |
| 최악 | $O(n^2)$ | 이미 정렬된 배열 + 끝 원소를 피벗으로 선택 |

공간 복잡도는 재귀 스택의 깊이에 비례해 $O(\log n)$이며, 최악의 경우 $O(n)$까지 증가할 수 있습니다.

## SQL에서의 정렬

데이터베이스는 `ORDER BY` 절을 처리할 때 내부적으로 정렬 알고리즘을 사용합니다. PostgreSQL의 경우 기본적으로 **외부 병합 정렬**(external merge sort)을 사용하지만, 데이터 크기가 `work_mem` 안에 들어오면 **quicksort**로 전환됩니다.

```sql title="order_by_example.sql"
-- 인덱스가 없는 컬럼을 정렬 → Quick Sort 또는 Merge Sort 사용
EXPLAIN ANALYZE
SELECT id, name, created_at
FROM users
ORDER BY created_at DESC  -- [!code highlight]
LIMIT 100;

-- 실행 계획에 "Sort Method: quicksort" 가 나타나면 메모리 내 정렬
-- "external merge" 가 나타나면 디스크 기반 정렬로 전환된 것
```

<Callout type="warning" title="인덱스 우선 검토">
  정렬이 빈번한 쿼리라면 Quick Sort가 호출되지 않도록 **정렬 컬럼에 인덱스를 생성**하는 편이 훨씬 빠릅니다. 정렬된 인덱스를 그대로 읽으면 $O(n \log n)$ 정렬 비용 자체가 사라집니다.
</Callout>

## 주의사항

Quick Sort를 쓸 때 자주 마주치는 함정들입니다.

<Callout type="error" title="이미 정렬된 배열에서의 최악 성능">
  끝 원소를 피벗으로 고르는 단순한 구현은 이미 정렬된 배열 또는 역순으로 정렬된 배열에서 $O(n^2)$로 성능이 붕괴됩니다.
</Callout>

프로덕션 코드에서는 반드시 아래 대응 전략 중 하나를 적용해야 합니다.

<Note title="피벗 선택 대응 전략">
  - **Median of three**: 첫/중간/끝 원소 중 중앙값을 피벗으로 선택
  - **Random pivot**: 매 파티션에서 랜덤 인덱스 선택
  - **Introsort**: Quick Sort가 재귀 깊이 임계값을 넘으면 Heap Sort로 fallback
</Note>

대부분의 경우 언어 표준 라이브러리의 정렬이 Quick Sort 또는 그 개량판을 내부에서 사용하며, 이미 위의 함정을 모두 해결해뒀습니다. 특별한 이유(in-place 요구사항, 특정 비교 로직 최적화 등)가 없다면 직접 구현보다 표준 라이브러리를 쓰세요.

<Note title="언어별 표준 정렬 구현">
  - **Java**: `Arrays.sort(int[])` → Dual-Pivot Quicksort
  - **Python**: `list.sort()` / `sorted()` → Timsort (Quick Sort 아님)
  - **Rust**: `slice::sort_unstable()` → Pattern-defeating Quicksort (pdqsort)
  - **Kotlin**: JVM의 `Arrays.sort()` 를 그대로 사용
</Note>
