이 글은 쿠버네티스 명령어와 YAML 템플릿의 누적 색인입니다. 깊은 동작·트레이드오프는 다루지 않고, 한 줄 명령과 최소 YAML로 빠르게 찾을 수 있는 자리에 둡니다. 새 쿠버네티스 개념 글이 추가될 때마다 해당 리소스 섹션이 한 묶음씩 늘어납니다.

## 사용법

- 좌측 목차에서 리소스명으로 점프합니다.
- 각 리소스 섹션은 (1) 핵심 명령 표, (2) 최소 YAML, (3) 깊은 설명 글 링크의 3 부분으로 구성됩니다.
- 깊은 동작·옵션 전체·트레이드오프는 이 글에서 다루지 않습니다. 각 섹션 끝의 `<RelatedPost>` 링크를 따라가면 개념 글에서 확인할 수 있습니다.
- 명령 표의 `<...>` 표기는 사용자가 채울 자리입니다.

## kubectl 기본

리소스 종류와 무관하게 자주 쓰는 명령입니다. 모든 리소스 섹션에서 공통으로 사용합니다.

| 명령 | 설명 | 비고 |
|---|---|---|
| `kubectl cluster-info` | 클러스터 엔드포인트 확인 | 첫 연결 점검 |
| `kubectl get <resource>` | 리소스 목록 조회 | `-A`로 모든 namespace |
| `kubectl get nodes` | 노드 목록 조회 | `-o wide`로 IP·OS 표시 |
| `kubectl get <resource> <name> -o yaml` | 한 객체의 YAML 덤프 | 디버깅 시작점 |
| `kubectl describe <resource> <name>` | 객체 상세와 이벤트 | 실패 원인 추적 |
| `kubectl run <name> --image=<image>` | Pod 즉석 생성 | demo·디버깅용. 실서비스는 Deployment |
| `kubectl apply -f <file>.yaml` | YAML로 리소스 생성·갱신 | 멱등 적용 |
| `kubectl delete <resource> <name>` | 객체 삭제 | `--grace-period=0 --force`로 강제 |
| `kubectl edit <resource> <name>` | 클러스터의 객체 즉시 편집 | `EDITOR` 환경변수 사용 |
| `kubectl logs <pod>` | 컨테이너 로그 | `-f` 추적, `-c <name>` 컨테이너 지정 |
| `kubectl exec -it <pod> -- <cmd>` | 컨테이너 안에서 명령 실행 | `-c`로 컨테이너 지정 |
| `kubectl port-forward <pod> <local>:<remote>` | 로컬 포트로 터널 | 로컬 디버깅 |
| `kubectl config use-context <name>` | 클러스터 컨텍스트 전환 | `kubectl config get-contexts`로 목록 |

### 출력 형식 옵션

| 옵션 | 효과 |
|---|---|
| `-o yaml` | 객체 전체 YAML |
| `-o json` | JSON. `jq`와 결합해 필터 |
| `-o wide` | 추가 칼럼 (노드, IP) |
| `-o jsonpath='{.spec.x}'` | 특정 필드 한 값 |
| `--watch` | 변경 스트림 |

## Namespace

한 클러스터 안에서 리소스 이름·정책·한도를 격리하는 단위. 같은 이름의 리소스가 다른 Namespace에 공존할 수 있습니다.

### 명령

| 명령 | 설명 | 비고 |
|---|---|---|
| `kubectl create namespace <name>` | Namespace 생성 | 한 줄 명령 |
| `kubectl apply -f namespace.yaml` | YAML로 Namespace 생성·갱신 | 선언적 |
| `kubectl get namespaces` | Namespace 목록 조회 | `ns`로 단축 |
| `kubectl get pods --namespace=<name>` | 특정 Namespace의 파드 조회 | `-n` 단축 |
| `kubectl get pods --all-namespaces` | 모든 Namespace 한꺼번에 | `-A` 단축 |
| `kubectl config set-context --current --namespace=<name>` | 현재 컨텍스트의 기본 Namespace 전환 | 이후 `-n` 생략 가능 |
| `kubectl delete namespace <name>` | Namespace와 그 안의 모든 리소스 삭제 | 자식 리소스 함께 정리 |

### 최소 YAML

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: dev
```

리소스를 특정 Namespace에 만들려면 매니페스트의 `metadata.namespace`에 적습니다.

```yaml
metadata:
  name: myapp-pod
  namespace: dev
```

서비스 FQDN의 형식은 `<service-name>.<namespace>.svc.cluster.local`입니다. 같은 Namespace 안에서는 짧은 호스트명만으로 충분합니다.

## Pod

쿠버네티스가 컨테이너를 한 단위로 묶어 스케줄·재시작하는 가장 작은 오브젝트입니다.

### 명령

| 명령 | 설명 | 비고 |
|---|---|---|
| `kubectl create -f <file>.yaml` | YAML로 Pod 생성 | 이미 있으면 실패 |
| `kubectl get pods` | Pod 목록 조회 | `-A` 모든 namespace |
| `kubectl describe pod <name>` | Pod 상세와 이벤트 | 시작 실패 원인 추적 |
| `kubectl run <name> --image=<image>` | Pod 즉석 생성 | demo·디버깅용 |

### 최소 YAML

#### 단일 컨테이너 Pod

```yaml title="single-container-pod.yaml"
apiVersion: v1
kind: Pod
metadata:
  name: myapp-pod
  labels:
    app: front-end
spec:
  containers:
    - name: nginx-container
      image: nginx
```

#### 멀티 컨테이너 Pod (사이드카)

```yaml title="sidecar-pod.yaml"
apiVersion: v1
kind: Pod
metadata:
  name: myapp-pod
  labels:
    app: front-end
spec:
  containers:
    - name: app
      image: myapp:1.0
      ports:
        - containerPort: 8080
    - name: log-agent
      image: fluent-bit:latest
```

## ReplicaSet

선언된 수만큼 같은 파드가 항상 돌도록 유지하는 컨트롤러.

### 명령

| 명령 | 설명 | 비고 |
|---|---|---|
| `kubectl apply -f rs.yaml` | RS 생성·갱신 | 선언적, 멱등 |
| `kubectl get replicaset` | RS 목록 조회 | `rs`로 단축 |
| `kubectl describe replicaset <name>` | 상세와 이벤트 | 디버깅 시작점 |
| `kubectl delete replicaset <name>` | RS와 관리 Pod 삭제 | |
| `kubectl scale --replicas=N replicaset <name>` | 복제본 수 즉시 조정 | YAML은 변경 안 됨 |
| `kubectl replace -f rs.yaml` | RS를 파일로 통째 대체 | apply가 권장 |

### 최소 YAML

```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: myapp-replicaset
spec:
  replicas: 3
  selector:
    matchLabels:
      tier: frontend
  template:
    metadata:
      labels:
        tier: frontend
    spec:
      containers:
        - name: nginx
          image: nginx
```

set-based selector 변형은 다음과 같이 `matchExpressions`를 추가합니다.

```yaml
spec:
  selector:
    matchLabels:
      tier: frontend
    matchExpressions:
      - key: env
        operator: In
        values: [staging, production]
```

## ResourceQuota

한 Namespace가 동시에 가질 수 있는 자원의 상한을 선언하는 객체. 한도를 넘기는 요청은 `kubectl apply` 단계에서 거절됩니다.

### 명령

| 명령 | 설명 | 비고 |
|---|---|---|
| `kubectl apply -f quota.yaml` | ResourceQuota 생성·갱신 | 선언적 |
| `kubectl get resourcequota --namespace=<name>` | 해당 Namespace의 quota 조회 | `quota`로 단축 |
| `kubectl describe resourcequota <name> --namespace=<ns>` | 사용량과 한도 동시 확인 | 디버깅 시작점 |
| `kubectl delete resourcequota <name> --namespace=<ns>` | quota 삭제 | 한도 해제 |

### 최소 YAML

```yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: compute-quota
  namespace: dev
spec:
  hard:
    pods: "10"
    requests.cpu: "4"
    requests.memory: 5Gi
    limits.cpu: "10"
    limits.memory: 10Gi
```

`hard`의 각 항목이 해당 Namespace의 동시 보유 상한선입니다. `pods`는 개수, `requests.*`는 스케줄링 시 요청 합, `limits.*`는 컨테이너 한도 합을 가리킵니다.
