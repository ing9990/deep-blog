Claude Code는 터미널에서 돌아가는 AI 코딩 에이전트지만, 개발자만 쓰는 도구가 아닙니다. 파일을 읽고 고치는 모든 업무(특허 명세서, OA 대응, 청구항 초안, 엑셀 관리)에서 똑같이 유용합니다. 이 글은 비개발자가 자신의 업무에 맞게 Claude Code를 세팅할 수 있도록, 설치부터 4가지 확장 축의 설계 원리까지를 한눈에 안내합니다.

<Callout type="info" title="이 글의 학습 목표">
  1. Claude Code가 일반 챗봇과 어떻게 다른지 이해한다
  2. 네 가지 확장 축(CLAUDE.md·Skills·Agents·Plugins)의 역할을 구분할 수 있다
  3. 내 업무에 맞는 커스터마이징 방향을 선택하는 기준을 얻는다
</Callout>

## Claude Code란

**Claude Code**는 Anthropic이 만든 터미널 기반 AI 코딩 에이전트입니다. 비개발자를 위해 풀어쓰면, 여러분 컴퓨터 안에 사는 AI 동료인데 대화만 하는 것이 아니라 **실제로 파일을 읽고·고치고·명령어를 실행하는** 존재입니다.

일반 챗봇과의 결정적 차이는 도구(tools)를 쥐고 있다는 점입니다. 예를 들어 ChatGPT나 Claude.ai 웹은 "이 파일 어떻게 바꿔야 해?"를 물으면 답을 돌려주지만, 실제 파일을 열거나 고쳐주지는 않습니다. Claude Code는 다릅니다.

| 질문 | 일반 챗봇 | Claude Code |
|---|---|---|
| 이 프로젝트 구조 봐줘 | 불가 (못 봄) | 실제로 디렉토리를 읽어서 봄 |
| 이 함수 고쳐줘 | 고친 코드를 복붙으로 돌려줌 | 실제 파일을 직접 편집함 |
| 테스트 돌려줘 | 불가 | 터미널에서 명령 실행 |
| PR 만들어줘 | 불가 | GitHub CLI로 실제 PR 생성 |

이 실행 능력이 에이전트(agent)라는 단어의 의미입니다.

## 왜 필요한가

"AI에게 파일 읽기·쓰기 권한까지 왜 주는가?"에 답이 되려면, 웹 챗봇의 한계를 한 번 짚어야 합니다. 챗봇에게 100페이지 명세서를 검토시키려면 복사·붙여넣기를 반복해야 하고, 그 답을 다시 파일로 옮겨 적어야 합니다. 이 왕복에서 대부분의 시간이 새어 나갑니다.

Claude Code는 이 왕복을 없앱니다. 파일을 직접 읽고, 수정안을 직접 반영하고, 명령을 직접 실행합니다. 대신 **매 작업마다 여러분의 승인**을 받습니다. 이 설계가 두 가지 효과를 만듭니다.

- **왕복 제거**: "읽어서 → 판단해서 → 고치고 → 저장"이 한 대화 안에서 끝납니다.
- **재현성**: 규칙을 파일로 적어두면 다음 세션·다른 PC에서도 동일한 품질이 나옵니다.

흔한 오해 하나. Claude Code는 개발자만 쓰는 도구가 아닙니다. 특허 명세서 작성, 회계 스프레드시트 자동화, 리서치 자료 요약 등 **파일 기반 작업이 있는 모든 영역에서 유용**합니다. 단, 파일 구조와 권한 개념은 조금 익혀야 합니다 (이 글의 목적).

## 설치와 첫 실행

Claude Code는 여러분 컴퓨터 안에서 돌아가는 프로그램입니다. 브라우저에서 Claude.ai에 접속하는 것과 달리, 파일을 직접 읽고 고치려면 여러분 컴퓨터에서 돌아가야 하거든요. 그래서 한 번 설치하는 과정이 필요합니다.

2026년 현재 설치는 **명령어 한 줄**로 끝납니다. 예전에는 Node.js니 npm이니 복잡한 준비가 필요했지만, 지금은 공식 설치 스크립트가 그 모든 걸 알아서 처리합니다.

"명령어를 어디에 치라는 거지?" 하는 분을 위해 짚고 넘어갑니다. 터미널(Terminal)이라는 검은 화면에 입력합니다. 여는 법만 기억하세요.

- **macOS**: `Command + Space` 눌러 Spotlight 열고 "Terminal" 입력
- **Windows**: 시작 메뉴에서 "PowerShell" 검색

### 전체 흐름

세 단계면 끝납니다.

1. **설치**: 한 줄 명령어로 끝
2. **실행**: 작업 폴더에서 `claude` 입력
3. **브라우저 로그인**: Claude 계정 인증
4. **준비 완료**: 자연어로 지시 시작

### 설치

사용 중인 운영체제 탭을 선택하세요.

### 설치 확인

터미널을 완전히 닫았다가 **다시 열고** 다음을 실행.

```bash
claude --version
```

버전 번호가 나오면 성공입니다. `command not found`가 나오면 터미널을 재시작하거나 컴퓨터를 다시 시작해보세요.

### 실행

작업할 **프로젝트 폴더** 안에서 `claude`를 실행합니다. 아직 프로젝트가 없다면 빈 폴더 하나를 만들어도 괜찮습니다.

```bash
cd ~/Documents/my-project   # 작업 폴더로 이동
claude                       # Claude Code 실행
```

### 브라우저 로그인

처음 실행하면 브라우저가 자동으로 열리며 로그인 화면이 나타납니다. 다음 중 하나로 로그인할 수 있습니다.

| 로그인 방법 | 누가 쓰나 |
|---|---|
| Claude Pro / Max 계정 | 개인 구독자 (가장 일반적) |
| Claude for Teams / Enterprise | 회사 계정 |
| Claude Console API 키 | 사용량 기반 결제 선호 |

로그인하면 터미널에 프롬프트가 나타납니다.

```text
Welcome to Claude Code
/help for help, /status for info

>
```

이 `>` 옆에 자연어로 말을 걸면 됩니다.

### 첫 대화와 권한 팝업

`>` 뒤에 한국어나 영어로 아무거나 지시해보세요.

```text
> 이 폴더에 어떤 파일들이 있는지 알려줘
```

이 순간 Claude는 파일을 보기 위해 `Glob` 도구를 쓰려 합니다. 하지만 곧바로 실행하지 않고 **이 도구를 써도 될까요?** 를 팝업으로 묻습니다. **Yes** 를 누르면 실행되고, **No** 면 다른 방법을 찾습니다. 이 팝업이 Claude Code의 안전장치입니다. AI가 여러분 동의 없이 파일을 건드리거나 이상한 명령을 실행할 수 없도록 하는 장치죠. 익숙해지면 자주 쓰는 도구는 항상 허용으로 설정해 팝업을 줄일 수 있습니다 (`/config`).

### 슬래시 명령어

`>` 프롬프트에 `/`를 치면 명령 목록이 뜹니다. 초반에 쓸 만한 것들.

| 명령어 | 용도 |
|---|---|
| `/help` | 사용 가능한 명령 목록 |
| `/status` | 로그인 상태, 현재 모델, 프로젝트 정보 확인 |
| `/clear` | 대화 기록 초기화 (새 작업 시작할 때) |
| `/config` | 설정 변경 (모델, 자동 업데이트, 권한 등) |
| `/login` · `/logout` | 계정 전환 · 로그아웃 |
| `/init` | 현재 폴더를 Claude Code 프로젝트로 초기화 |

### 자주 겪는 문제

**1. `claude: command not found`**
터미널을 완전히 닫았다가 다시 여세요. 그래도 안 되면 컴퓨터 재시작.

**2. 로그인 브라우저가 자동으로 안 열림**
터미널 화면에 표시되는 URL을 복사해서 브라우저 주소창에 직접 붙여넣으세요.

## 동작 원리

<Callout type="warning" title="이 글의 핵심 포인트">
  Claude Code의 작동 원리는 단 두 축으로 요약됩니다. **매 세션 기억 리셋**과
  **파일 기반 규칙 로드**. 이 조합이 개인·팀·법인 단위의 환경 이식성을 만듭니다.
</Callout>

세팅된 Claude Code가 자동으로 법인 기준대로 동작하는 이유는 **두 가지 원리** 때문입니다.

### Context

Context는 Claude가 **지금 머릿속에 담고 있는 정보 전부**입니다. 지시한 말, 읽은 파일, 실행 결과가 모두 이 책상 위에 쌓입니다.

**규칙 하나**: 매 `claude` 실행 시 책상은 **비어 있는 상태로 시작**합니다. 오늘 알려준 규칙도 내일이면 사라집니다.

### CLAUDE.md

이 기억 리셋 문제를 해결하는 게 `CLAUDE.md`입니다. 프로젝트 폴더에 이 파일을 두면 Claude Code는 **매 세션 시작 시 자동으로 Context에 로드**합니다.

<Callout type="warning" title="CLAUDE.md가 너무 길어지면">
  CLAUDE.md는 세션마다 통째로 책상 위에 먼저 올라갑니다. 수백·수천 줄로 길어지면 그만큼 책상 공간을 차지해 응답 속도·품질이 떨어집니다. 핵심만 간결하게 작성하세요. 상세 작성법은 **2편 「CLAUDE.md 작성법」**에서 다룹니다.
</Callout>

### Context 구성 요소

| 들어가는 것 | 예시 |
|---|---|
| 현재 세션 대화 | "이 폴더 뭐 있어?" → Claude 답변 |
| 열어본 파일 내용 | 명세서(한글), 선행문헌(PDF), 출원 현황(Excel) |
| 실행한 명령 결과 | `pdftotext` 출력, 디렉토리 목록 |
| `CLAUDE.md` (항상) | 법인 공통 규칙 |

이 네 가지가 섞여 하나의 대화 맥락을 이룹니다.

<Callout type="error" title="핵심 통찰: 리셋을 전제로 한 파일 기반 협업">
  Claude Code는 매 세션 기억을 리셋합니다. 이는 불편이 아니라 **설계 선택**입니다. 리셋을 전제로 CLAUDE.md·Skills·Agents·Plugins가 파일로 규칙을 기술하게 되고, 그 결과 Git으로 공유·버전 관리·팀 배포가 자연스럽게 따라옵니다. 다음 섹션의 4가지 확장 축은 이 원리의 네 변주입니다.
</Callout>

## 4가지 확장 축

CLAUDE.md 외에 Context를 넓히는 세 가지가 더 있습니다. **Skills / Agents / Plugins**. 네 축은 단순히 문서를 여러 폴더로 쪼갠 게 아니라, **각자 답하는 질문이 다릅니다**.

| 축 | 답하는 질문 | 비유 |
|---|---|---|
| `CLAUDE.md` | Claude가 이 프로젝트에서 항상 알아야 할 것은? | 벽에 붙은 사무실 규정 |
| **Skills** | Claude가 해낼 수 있어야 할 반복 업무는? | 캐비닛 속 매뉴얼 |
| **Agents** | 독립된 방에서 제한된 도구로 끝내야 할 일은? | 별도 방에 들어가 결과만 들고 나오는 하위 담당자 |
| **Plugins** | 위 세 가지를 묶어 팀에 배포하려면? | 법인 표준 업무 키트 |

### 2×2 배치

네 축은 두 개의 질문으로 구분됩니다. **언제 Context에 로드되는가?** (항상 / 필요할 때)와 **어떤 Context에 로드되는가?** (메인 공유 / 독립 격리).

|  | 항상 로드 | 필요할 때만 로드 |
|---|---|---|
| **메인 Context 공유** | `CLAUDE.md` | **Skills** |
| **독립 Context (격리)** | 없음 | **Agents** |

Plugins는 위 세 축의 산물을 배포·공유 가능한 꾸러미로 묶는 별도 차원입니다.

### 각 축의 역할

**CLAUDE.md: 항상 지켜야 할 규칙**
청구항 어미 규칙, 원본 보호 규칙, 가명 처리 같은 **모든 시나리오에서 공통 적용**되는 법인 기준. 다음 섹션의 "커스터마이징 후" 열의 행동 변화는 대부분 CLAUDE.md가 만듭니다.
→ 상세: **2편 「CLAUDE.md 작성법」**

**Skills: 반복되는 업무 매뉴얼**
다음 섹션의 ① 선행기술조사, ④ OA 대응 초안, ③ 청구항 초안은 각각 하나의 Skill로 구현됩니다. 사용자가 해당 업무를 언급하면 Claude가 자동으로 꺼내 씁니다.
→ 상세: **3편 「Claude Code Skills 작성법」**

**Agents: 독립 공간의 하위 일꾼**
다음 섹션의 ⑤ 명세서 검토는 읽기 전용 권한으로 돌아가는 에이전트가 담당합니다. 대량 스캔·권한 격리·모델 별도 지정이 필요한 큰 작업에 적합합니다.
→ 상세: **4편 「Claude Code Agents 작성법」**

**Plugins: 팀 배포 꾸러미**
위 셋을 묶어 `patent-firm-kit` 플러그인으로 만들면, 직원 PC 한 번 설치로 법인 환경 전체가 세팅됩니다. 1편에서 개념만 짚고 넘어갑니다 (아래 한 단락).

### Skills vs Agents

Skills와 Agents는 모두 "특정 작업을 시킨다"는 점이 닮아 혼동됩니다. 결정 포인트는 **Context를 공유할지**입니다.

| 상황 | 선택 |
|---|---|
| 메인 대화 흐름에서 이어서 처리 (청구항 초안 받아 바로 검토 계속) | **Skills** |
| 메인 Context에 노이즈 없이 결과만 받기 (100페이지 PDF 전체 스캔) | **Agents** |
| 권한을 제한해야 함 (원본은 읽기만, 쓰기 금지) | **Agents** |
| 자주 쓰고 절차가 일관됨 | **Skills** |
| 한 번에 길게 돌아야 하고 결과만 중요 | **Agents** |

### Plugins 개요

Plugins는 **CLAUDE.md + Skills + Agents를 하나의 꾸러미로 묶는 배포 단위**입니다. 법인 표준 키트를 만들어 모든 직원 PC에 동일 환경을 세팅하려면 아래 구조로 정리합니다.

```text title="법인 키트 배포용 폴더 구조"
patent-firm-kit/
├── .claude-plugin/
│   └── plugin.json          ← 이름·버전·설명
├── skills/
│   ├── prior-art-search/
│   ├── claim-drafting/
│   └── oa-draft/
└── agents/
    └── spec-consistency-check.md
```

직원 PC에서는 한 번의 명령으로 설치 완료.

```text
/plugin install patent-firm-kit
```

플러그인 자체를 만드는 것은 세 축(CLAUDE.md·Skills·Agents)을 먼저 익힌 뒤에 시도해도 늦지 않습니다.

## 업무 예시

Claude Code가 어떤 일을 할 수 있는지 **특허법인의 실제 업무 흐름**으로 보여드립니다. 각 시나리오는 **사용자가 한 줄 지시** → **Claude가 자동 처리** → **결과물 산출** 구조입니다.

### 파일 포맷 준비

Claude Code는 기본적으로 텍스트를 다룹니다. 한국 특허 업무에서 자주 쓰는 PDF·한글·Excel·PPT는 **텍스트를 꺼내주는 보조 도구** 한 번 설치로 해결됩니다. 이 작업은 한 번만 하면 됩니다.

| 포맷 | 설치 명령 | 언제 필요한가 |
|---|---|---|
| PDF | (macOS 기본) · `brew install poppler` | 공개특허, OA 통지서, 등록특허 |
| 한글(HWP) | `pip install pyhwp` | KIPO 문서, 명세서, 청구항 문서 |
| Excel(XLSX) | 기본 지원 | 출원 현황, 용어집, 비교표 |
| PPT(PPTX) | `pip install python-pptx` | 고객 미팅 자료 |

CLAUDE.md에 "`prior-art/*.pdf`는 `pdftotext`로, `.hwp` 파일은 `pyhwp`로 추출한다" 같은 한 줄만 적어두면 Claude가 알아서 씁니다.

### ① 선행기술조사

**상황**: 새 출원 전, 유사 선행문헌 50건을 수작업으로 읽고 비교표 만들기. 기존 2–3일 소요.

**사용자 지시**:

```text
> prior-art/ 폴더 PDF 스캔해서 "배터리 셀 냉각" 주제 관련 비교표 만들어줘
```

**Claude가 하는 일**:

- 폴더 내 PDF 50건을 `pdftotext`로 텍스트 추출
- 각 문서에서 발명의 명칭·독립항·출원인·출원일 파싱
- 주제 관련성 O/△/X 1차 분류
- `review/prior-art-2026-04-17.md`에 표 저장

**결과물**: Markdown 비교표. Excel로 원하면 "xlsx로 내보내줘" 한 줄 추가.

### ② 유효 문건 판별

**상황**: 등록특허의 무효 사유를 찾기 위해 공개특허 수백 건 검토. 1차 스크리닝만 AI에 맡기고 사람은 shortlist만 본다.

**사용자 지시**:

```text
> candidates/ PDF들을 "리튬이온 양극재 조성"과의 관련성 기준으로 분류해서 O·△ 건만 따로 빼줘
```

**Claude가 하는 일**:

- 에이전트로 병렬 스캔 (메인 세션 깨끗하게 유지)
- 핵심 키워드 hit + 청구항 요지 매칭
- 관련성 O/△만 `candidates/shortlisted/`로 복사
- 분류 사유 요약 리포트 작성

**결과물**: Shortlist 폴더 + 분류 사유 리포트. 변리사는 shortlist만 정독.

### ③ 청구항 초안

**상황**: 고객이 보낸 한글 발명 설명서(`invention-disclosure.hwp`)를 기반으로 첫 청구항 초안.

**사용자 지시**:

```text
> invention-disclosure.hwp 읽고 독립항 1개 + 종속항 5개 초안 작성. 법인 어미 규칙 지켜서.
```

**Claude가 하는 일**:

- `pyhwp`로 한글 파일 텍스트 추출
- 구성요소·효과·실시예 분리 파싱
- CLAUDE.md의 어미 규칙("~을(를) 포함하는") 자동 적용
- 고객사별 용어집 자동 참조
- `drafts/claims-<출원번호>.md`에 초안 저장

**결과물**: Markdown 청구항 초안. 변리사는 검토·수정에만 집중.

### ④ OA 대응 초안

**상황**: KIPO에서 수신한 거절이유통지서(`.hwp`) + 인용 문헌 PDF. 반박 논거 구상이 가장 힘든 단계.

**사용자 지시**:

```text
> oa-notice-2026-04-15.hwp 분석하고 cited/ 의 인용 문헌들과 비교해서 반박 논거 초안 써줘
```

**Claude가 하는 일**:

- OA 한글 파일에서 거절 이유·인용 문헌 번호 추출
- 각 인용 문헌 PDF를 읽어 우리 출원과의 차이점 분석
- 법인 표준 구조(쟁점 → 선행문헌 분석 → 차이점 → 반박 논거) 로 초안 작성
- CLAUDE.md 규칙대로 한/영 병기

**결과물**: `drafts/oa/<사건번호>/response-v1.md`. 변리사는 논거의 톤·강도만 조율.

### ⑤ 명세서 검토

**상황**: 100페이지 명세서(`.hwp`) 제출 직전. 용어 혼용·도면 번호 누락 등 사소하지만 결정적인 이슈를 놓치면 안 되는 단계.

**사용자 지시**:

```text
> spec/working/ 명세서 일관성 검증 에이전트 돌려줘
```

**Claude가 하는 일**:

- `spec-consistency-check` 에이전트 호출 (읽기 전용 권한)
- 용어 혼용·도면 번호 누락·부호 불일치·청구항 미대응 스캔
- 이슈를 위치·심각도별로 표 작성

**결과물**: 이슈 목록 표. 변리사는 표의 행을 하나씩 클리어하면 검토 종료.

### ⑥ 출원 현황 관리

**상황**: 수백 건 출원을 관리하는 `filings.xlsx`. 매주 월요일 마감일 임박 건을 수작업으로 뽑던 업무.

**사용자 지시**:

```text
> filings.xlsx 읽고 다음 7일 이내 마감 건 정리해줘. OA 대응·심사청구·연차료로 분리하고 담당 변리사별 그룹.
```

**Claude가 하는 일**:

- Excel을 읽어 각 행 파싱 (출원번호·명칭·마감일·유형·담당자)
- 오늘 기준 7일 이내 필터
- 유형·담당자별 그룹핑
- `review/weekly-deadlines-<날짜>.md`에 목록 저장

**결과물**: 월요일 아침 바로 쓸 수 있는 주간 마감일 목록. 팀에 공유.

### ⑦ 고객 미팅 자료

**상황**: OA 대응 결과를 고객사에 30분 미팅으로 보고. 슬라이드 만드는 데 반나절 소요.

**사용자 지시**:

```text
> drafts/oa/case-2026-123/ 결과로 고객 보고용 슬라이드 초안 만들어줘. 8장 이내.
```

**Claude가 하는 일**:

- OA 대응 초안 읽기
- 슬라이드 구조 설계 (배경 → 거절이유 → 대응 전략 → 예상 결과 → 다음 단계)
- 각 장의 제목·본문·핵심 수치 텍스트로 작성
- `slides/client-briefing.md`에 초안 저장

**결과물**: Markdown 슬라이드 아웃라인. `python-pptx` 스킬이 있다면 `.pptx`로 자동 변환까지.

### 커스터마이징 효과

같은 "선행기술조사 해줘" 한 줄이라도 **커스터마이징 여부에 따라** 결과가 크게 달라집니다.

| | 기본 상태 (설치만 한 Claude Code) | 커스터마이징 후 (CLAUDE.md + Skills) |
|---|---|---|
| 비교표 형식 | Claude가 매번 임의 결정 | 법인 표준 포맷 자동 적용 |
| 고객사명 노출 | 실명 그대로 | 가명 규칙 자동 적용 |
| 저장 위치 | 매번 물어봄 | `review/prior-art-<날짜>.md` 자동 |
| 용어 일관성 | 혼재 가능 | 고객사별 용어집 자동 참조 |
| 청구항 어미 | 일관성 없음 | "~을(를) 포함하는" 자동 적용 |
| OA 대응 구조 | 매번 달라짐 | 쟁점→분석→차이점→반박 표준 구조 |
| 원본 파일 보호 | 실수로 덮어쓸 위험 | 에이전트 권한으로 읽기 전용 강제 |

CLAUDE.md + Skills를 한 번 세팅해 Git으로 공유하면, 어떤 직원이 어떤 PC에서 `claude`를 켜도 법인의 품질 기준이 자동으로 적용됩니다. 이게 Claude Code를 개인 도구가 아니라 **법인의 표준 업무 환경**으로 만드는 핵심입니다.

## 마무리

여기까지 읽었다면 Claude Code의 설치·실행·4축 지도를 모두 잡은 셈입니다. 이 지도만 있으면 "어디에 무엇을 적어야 하지?"로 더 이상 헤매지 않습니다.

기억할 것 세 가지.

1. **CLAUDE.md는 항상 로드되는 짧은 규칙서**: 200줄 이내로 간결하게
2. **Skills는 반복 업무 매뉴얼**: description으로 자동 호출
3. **Agents는 독립된 방의 하위 일꾼**: 권한 격리·대량 처리·모델 별도 지정

이제 **2편 「CLAUDE.md 작성법」** 부터 차근차근 커스터마이징을 시작해보세요. 법인에 꼭 맞는 AI 업무 환경이 손에 잡힐 겁니다.
